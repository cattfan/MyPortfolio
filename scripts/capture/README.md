# Project UI Captures

The public portfolio shows two projects: Riviu Manager and Riviu Web. Manager uses source-rendered fixture captures; Riviu Web uses public production captures from `https://taskscatt.click/`. The UI omits source-code links and repeated demo labels. Capture metadata retains the original provenance, including archived Reports and ShopOfCatt images. None of these scripts publish deployments, run device workflows, submit forms, create orders or process payments.

## Active Public Website

Run from the workspace root with `PLAYWRIGHT_CHROMIUM_EXECUTABLE` pointing to a local Chromium executable:

```powershell
node scripts/capture/riviu-live.mjs
node scripts/capture/verify-live-sites.mjs MODIFIED
```

Riviu Web uses `https://taskscatt.click/` and `/bang-gia#combo`. Its script writes `live-overview.png/webp`, `live-detail.png/webp` and `live-capture.json`, preserving earlier captures. Screenshots are 2880x1800. A fresh browser context has no signed-in user; normal page analytics may run. Metadata records exact URLs, HTTP status, date, image hashes and browser errors. The existing `cattshop-live.mjs` script and its output remain archive tooling, not part of the current public project selection.

`verify-live-sites.mjs MODIFIED` validates two projects, one website link, two selected live photos and their four PNG/WebP files. It checks internal source flags rather than visible demo labels. `BASELINE` and `ROLLBACK` validate the previous three-project snapshot; pass the snapshot root as the third argument. A fourth argument can point to the unchanged asset root when a snapshot contains only source files.

Source hash coverage varies by script, so keep the source repos idle during capture.

## Prerequisites

- Node.js 24+ and Git; pnpm dependencies already installed in MyBlog and the source frontends.
- MyBlog's `apps/web` dependencies include Playwright and Sharp. Manager requires its existing Vite dependencies. ShopOfCatt requires its already-built `@webcatt/shared` workspace package.
- A local Chromium executable. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` explicitly for all scripts; the example below uses installed Chrome.
- Free ports: Manager `1421`, Riviu Web `3104`/`4104`, ShopOfCatt `3105`/`4105`. Reports chooses an available local port. Manager and Riviu Web support `MANAGER_CAPTURE_PORT`, `RIVIU_CAPTURE_PORT` and `RIVIU_FIXTURE_PORT` overrides.

Run from the MyBlog root in PowerShell:

```powershell
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE = "C:\Program Files\Google\Chrome\Application\chrome.exe"
node scripts/capture/manager-reports.mjs
node scripts/capture/riviu-web.mjs
node scripts/capture/shop-of-catt.mjs
```

The scripts stop their own local frontend and fixture servers when finished. They keep the source application styles and markup; only Next.js developer controls are hidden from web captures. Fonts, images and initial rendering are allowed to settle before capture.

## Outputs And Review

Outputs go to `apps/web/public/projects/{riviu-manager,riviu-reports,riviu-web,shop-of-catt}/`, never to `note`. Each project has `overview.png`, `detail.png`, corresponding `.webp` files and `capture.json`. PNG originals are 2880x1800 from a 1440x900 viewport at 2x density. Manager/Reports WebP copies are 1920x1200; the other two retain the original dimensions.

After every recapture, open both screens and confirm readable text, loaded assets, meaningful framing and no loading/error overlays. Inspect metadata for browser errors and source-state checks before updating the portfolio. Fixture values and archived catalog artwork are demonstration material; record that in metadata without treating it as a verified business result.
